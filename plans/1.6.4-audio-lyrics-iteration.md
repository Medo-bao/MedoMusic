## 1. 主增益 + 立体声平衡

### DSP（`src/fxsound-core.js`）

新增两个纯增益函数与一个链路阶段：

- `masterGain(db)`：`10^(dB/20)`，范围 ±20 dB（GainEq 文档值）。
- `balanceGain(db)`：按原生 SOS 的 dB 差衰减一侧。
  `-20 dB` → 左 1 / 右 0.1，`0 dB` → 全 1，`+20 dB` → 左 0.1 / 右 1，
  负值偏左、正值偏右，居中两侧均为 1，不引入等功率声像的电平跳变。
- `Chain.applyMasterTrim(output, settings)`：在 EQ 之后、效果组之前，主增益作用于
  单声道、立体声、5.1、7.1 的所有声道；平衡仅用于立体声，四声道按原生路径跳过
  GraphicEq 与这两项处理，与上游 GraphicEq / SOS 的位置和声道分支一致。主增益放在
  效果链之前而不是之后，因此正增益会被 Maximizer 的电平检测部分吸收——这与原生
  行为相同，已在报告里注明。
- `FxSoundChain` worklet 新增 `masterGain`、`balance` 两个 `k-rate` 参数
  （默认 0、范围 -20~20）；参数描述符总数 31 个（20 段 + 9 效果控制 + 2 增益）。

### 参数模型（`src/sound-enhancement.js`）

- 新增 `MASTER_GAIN_RANGE`、`BALANCE_RANGE`。
- `normalize()` 对两级做钳制，非法值回落为 0。
- `flat` / `recommended` 预设都带上 `masterGain: 0, balance: 0`。

### UI（`src/index.html`、`src/renderer.js`、`src/styles.css`）

- 音效卡片新增「主增益」「立体声平衡」两条滑块，`output` 显示 `+3 dB` / `居中` /
  `左 +6 dB`（表示左右电平差，不额外提升该侧）。
- 两个滑块都支持双击归零，`sound-reset` 一并复位。
- 音效卡片与 EQ 绘图区高度从 296 px 调到 300 px，以容纳 7 条控件并在 960×720 下
  不产生纵向滚动；EQ SVG 与 184 px 滑块使用相同坐标，中线为 92，
  `y = 92 − gain × (85/12)`，±12 dB 对齐 14 px 滑块拇指中心 7/177。

## 2. 效果量程校准

上游 `DfxDspPrivate::setEffectValue` 把 0–10 的旋钮值统一除以 10，五个效果的
控制域完全一致。本地原先内部量程为 clarity 0–4、bass 0–6、其余 0–100，
虽然百分比→MIDI 的映射恰好等价，但单位不统一，且报告里容易误读为「上限被压低」。

本次统一为 **0–100 单一量程**：

- `EFFECT_KEYS = ["clarity","ambience","surround","dynamics","bass"]`。
- `EFFECT_RANGE = { min: 0, max: 100 }`，`normalize()` 对五个键统一钳制。
- `presets.recommended` 换算到同一量程：clarity 10、bass 10（原先内部 0.4/0.6
  在归一化后仍是 10% 与 10%），ambience 18、surround 13、dynamics 15 不变。
- 渲染层不再出现 `key === "bass" ? 6 : key === "clarity" ? 4` 这种分支。

`normalize()` 只接收新单位；`fromStorage()` 在读取已发布 1.6.3 的
`medo.sound`、`medo.soundPresets`、`medo.soundCustom` 时，分别把 clarity ×25、
bass ×100/6，写入 `formatVersion: 2`，重复启动不再转换。
未带版本、但已带主增益/平衡字段的实验构建数据按百分比读取，避免把新设定的低百分比放大。

## 3. Apple Music TTML

### 新模块

- **`src/apple-ttml.js`**：TTML 解析。
  - 时间格式：`hh:mm:ss.mmm`、`mm:ss.mmm`、`1.5s`、`250ms`、`48f`、纯数字。
  - 音节：`<span begin=… end=…>`，无 `end` 时用下一个 span 的 `begin`。
  - 背景人声：`ttm:role="x-bg"` → `line.subline`。
  - 翻译：iTunes 命名空间中的 `<translation type="subtitle" xml:lang="zh-Hans">`
    与 `<text for="L1">`，按段落 `itunes:key="L1"` 对齐到 `line.translations.zh-hans`。
  - 注音：iTunes 命名空间中的 `<transliteration>` → `line.pronunciation`。
  - 使用 XML 命名空间 URI 识别元素/属性，前缀改名不改变结果；背景人声不重复进入主行。
  - 对唱：`<ttm:agent type="person">` 按顺序分配 `left` / `right`，
    `group` 保持 `unspecified`。
  - 作词人：`<itunes:songwriter>` 与 `<songwriters><songwriter>` 两种写法。
  - 同时导出 CommonJS 与 `window.MedoAppleTtml`（脚本直载也能用）。
- **`src/apple-music.js`**：provider。
  - `getDeveloperToken` 先读取 music.apple.com，再读取其 `assets/index*.js`，
    选择未过期的 WebPlay JWT，按缓存期限与 JWT 失效时间中较早者刷新。
  - `searchAppleSongs` → `/v1/catalog/{storefront}/search`。
  - `fetchAppleSyllableTtml` → `/v1/catalog/{storefront}/songs/{id}/syllable-lyrics`。
  - `createAppleLyricsFetcher` 返回与 QQ/网易同签名的
    `(options, fetch) => {text, source:"apple-word", confidence, match}`。
  - 没有 Media User Token 时直接返回 `null`，不发任何请求。
- **`src/apple-music-settings.js`**：凭据落盘。
  - 存在 `userData/apple-music.json`，字段 `mediaUserToken` / `storefront` / `enabled`。
  - 只通过 IPC 暴露 `configured` 布尔值；token 本身不进入 `localStorage`。
  - storefront 白名单校验。

### 接线

- `main.js`：`getAppleMusicFetcher()` 按 `storefront + token` 签名缓存 fetcher；
  `music:lyrics` 在搜索前读取凭据，把 `appleMusic` 布尔与 fetcher 一起传进
  `searchOnlineLyrics`。新增 `apple-music:get / update / clear` 三个 IPC。
- `lyrics-search.js`：新增 `appleMusic` fetcher 参数，provider 列表在启用时加入
  `"apple"`；自动模式会走 `rotation` 分支，而不是只认 `auto`。
- `lyrics-source-priority.js`：`resolveOnlineLyricProviders(mode, requireWordTiming,
  { appleMusic })`，逐字请求时把 apple 排在最前，普通请求追加在末尾。
- `preload.js`：暴露 `getAppleMusicSettings` / `setAppleMusicSettings` /
  `clearAppleMusicSettings`。
- `renderer.js` + `index.html`：歌词设置里新增「Apple Music 逐字歌词」开关、
  商店地区下拉、token 输入与保存/清除按钮；切换开关会重新拉取当前歌曲歌词。

## 4. 混合同步等级

- 新增 **`src/lyric-sync.js`**：`lyricSyncLevel(lines, hasTimeline)` 返回
  `plain | line | mixed | word`。
  - `information` 行（作词/作曲）不参与判定。
  - 只有部分行有 words → `mixed`。
  - 全部行都只有「整行近似」的词 → 仍算 `line`（不虚报逐字）。
- `renderer.js` 的 `finishLyricLines` 改为调用该模块，不再用单布尔
  `some(line => line.words.length)`。
- 渲染层：
  - `mixed` 时逐行显示 karaoke，只有行时间的行保持普通文本；
  - 提示语改为「部分歌词为逐字，其余 N 行仅逐行」；
  - 只有 `level === "line"` 时才提示「暂未找到逐字歌词」。

## 5. 多语言翻译字典

- `lyricTranslations` 的值从 `string[]` 改为 `Map<language, string[]>`。
  语言键复用 TTML 的小写形式（`zh-hans`、`zh-hant`、`ja-latn`…）。
- `pickChineseTranslation(line)` 按 `zh-hans/zh-cn/zh-sg` > `zh` > `zh-hant/zh-tw/zh-hk`
  的优先级选行内翻译。
- `lyricTranslationFor(trackId, lyrics, index)`：行内翻译优先，其次字典；
  同时兼容旧的 `string[]` 形态，避免历史缓存与既有测试失效。
- `ensureLyricTranslation` 把机器翻译结果与行内翻译合并，行内覆盖机器结果。
- `lyricsNeedChineseTranslation` 逐行检查覆盖情况；`ensureLyricTranslation` 只补没有中文
  翻译的外语行，保留原始行索引与已有的行内/缓存翻译，不因部分行已有翻译而跳过全曲。

## 7. 匹配质量三项

1. **编辑距离兜底**（`lyrics-matching.js`）
   - 新增 `textSimilarity`（LCS 百分比，对称）。
   - 标题精确/去版本/别名都未命中时，用模糊分兜底：> 80 → 0.85，> 68 → 0.7。
   - 艺人也允许模糊匹配（> 80），但仅在不共享别名时生效。
2. **艺人别名表**
   - `ARTIST_ALIAS_PAIRS` 收录 58 组常见「英文 ↔ 中文」艺人名。
   - 构建 `ARTIST_ALIASES` 反向索引，`artistAliases(token)` 展开为别名集合。
   - 中英文标签互查时命中，未知艺人仍回落到自身（不会全匹配）。
3. **QQ 翻译**
   - `decodeQqLyricJsonp` 现在同时解 `lyric` 与 `trans` 两个 base64 字段。
   - `alignQqTranslation` 把翻译按时间戳（±0.35 s）对齐到原文行。
   - `fetchQqMusicLyrics` 把对齐结果作为 `result.translation` 返回，
     `ensureLyrics` 收到后写入 `line.translations["zh-hans"]`。

## 9. 已知边界

- Apple Music 需要用户自己的 Media User Token；没有凭据时该 provider 完全不参与。
- 音量均衡 / 滤波器 Q / 5·15·31 段 EQ / 耳机模式按用户要求不在本次范围。
- 效果量程统一后，`clarity` 与 `bass` 的百分号含义与旧版一致（100% = 满 MIDI），
  但内部存储单位从 0–4 / 0–6 变为 0–100；旧 `localStorage` 数据由 `fromStorage()`
  迁移。已被早期实验构建改写且丢失单位来源的数据无法可靠反推，不按数值大小猜测单位。

## 11. normalization / volume leveling 与账号依赖取词清理

- 按原始 GraphicEq / SOS 移植两项独立控制，顺序为 EQ → master/balance → normalization → volume leveling → 五项效果；原算法必需的 Maximizer 保留。
- normalization 仅在 stereo 使用，目标 RMS 对应本地 -40–0 dBFS，0 关闭；只衰减，按原生规则缓慢恢复。volume leveling 为 0–4、0.5 步进，0 关闭；mono/stereo/surround 按原规则处理，surround 的 LFE 不参与。
- 两项默认 0，默认/作者推荐及旧预设不增加响度处理。预设保存、另存、*、双击复位和重置全部包含新参数；UI 位于调音台底部，原来的主增益/平衡位置保持。
- 匿名 Apple 实测：两首 hasLyrics=true 的曲目，在中/英文请求中均只返回目录信息而无歌词关系；直取路径 404，账号地区接口 403 并明确要求认证。
- 因不满足无登录使用条件，删除取词模块、凭据模块、设置入口、IPC 和来源编排；启动时删除旧凭据文件并清除旧偏好，歌词缓存升至版本 6。仅保留通用 TTML 离线格式解析及对应样例/署名。
- 固定 8 场景入口：tests/normalization-lyrics-acceptance.cjs；原始 C 参考工具 tests/fxsound-leveling-reference.cjs；**8/8 通过，渲染错误 0**，报告见 [本轮验收](../tests/artifacts/normalization-lyrics/results.json)。
- 原始 C 对照最大误差：normalization 4.47×10⁻⁸、volume leveling 1.20×10⁻⁷；默认关闭时旧链 24 组误差 0，实际 AudioWorklet 各声道对照误差 0。浅/深色与两种窗口尺寸的截图已查看，控件无横向溢出。
